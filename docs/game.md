# 僕が考えた最強のエンジニアたち！！

## 概要

Gitty上のあなたをソシャゲに！  
仲間を集め、大会で勝利をつかもう！

**キーワード**: シングルプレイ, マルチプレイ（非同期対人）, ソシャゲ

---

## ゲームの基本フロー

1. Gittyアカウントを連携し、自分のキャラクターを生成する
2. フレンドを追加し、デッキメンバーを集める
3. ハッカソン大会にエントリーし、デッキスコアが近い相手のデッキとシミュレーション対戦して開発スコアを競う
4. Gittyスコア更新でキャラクターを成長させる

---

## キャラクター

### 生成方法

Gittyプロフィールをスクレイピングし、キャラクターを自動生成する。

### レベルアップ

キャラクターのレベルアップは以下の2通りで発生する。

| トリガー          | 内容                                                                              |
| ----------------- | --------------------------------------------------------------------------------- |
| Gittyスコアの更新 | ゲーム内でGitty再スキャンを実行すると、最新スコアをもとに各スキル値が再計算される |

> **注意**: スキル値が下がることもある（リポジトリ活動が減少した場合など）。現実のエンジニア活動がそのままゲームに反映される。

### フレンドシステム

「フレンドに追加する」機能でフレンドのGittyURLを入力すると、そのエンジニアのデータからキャラクターが自動生成される。  
生成されたキャラクターは自分のデッキに組み込むことができる。

- フレンドのGittyスコアが更新されると、そのキャラクターにも反映される

#### 承認制オプション

ユーザーは設定から「フレンド追加を承認制にする」を有効化できる。

| 設定                          | 挙動                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------ |
| 承認制 **オフ**（デフォルト） | フレンド申請を受けると即時キャラクター生成を許可する                                       |
| 承認制 **オン**               | 申請通知が届き、承認した相手にのみキャラクター生成を許可する。拒否・無視した場合は生成不可 |

> 承認制をオンにしていても、自分からフレンド申請を送った相手については相手側の設定に関わらずキャラクター生成が可能。

## スキル

### スキルの種類と上限

すべてのスキルの上限値は **100**。

| スキル       | 概要                       | 算出方法                                                                                     |
| ------------ | -------------------------- | -------------------------------------------------------------------------------------------- |
| **実装力**   | コードを書く技術力全般     | `Gittyスコア × 0.01`                                                                         |
| **企画力**   | 言語化・ドキュメント力     | `(Readmeの充実度スコア + wiki / discussion数 × 0.5) / リポジトリ総数` → 0〜100にスケーリング |
| **継続力**   | 長期的なアウトプット維持力 | `アクティブ期間 / アカウント歴 × 100` → 0〜100にスケーリング                                 |
| **影響力**   | 他者からの評価・存在感     | `(リポジトリのスター数合計 × 0.5 + フォロワー数 × 1.0)` → 0〜100にスケーリング               |
| **開発速度** | アウトプットの速さ         | `(直近1年のコミット数 / 365 × 30) + PR平均解決日数ボーナス` → 0〜100にスケーリング           |

### スキル傾向（特化型 vs バランス型）

GitHubのアクティビティパターンを分析し、キャラクターに「特化型」または「バランス型」の傾向を付与する。  
「完璧なキャラクター」が生まれにくくなることで、デッキ構築の戦略性が生まれる。

| 傾向             | 条件                         | 特徴                                |
| ---------------- | ---------------------------- | ----------------------------------- |
| **実装特化型**   | コミット頻度が高い           | 実装力・開発速度↑ / 企画力・継続力↓ |
| **設計特化型**   | Readme / wiki / issueが充実  | 企画力↑ / 開発速度↓                 |
| **影響力特化型** | スター数・フォロワー数が多い | 影響力↑ / 開発速度↓                 |
| **バランス型**   | 偏りが少ない                 | すべてが中程度                      |

> **影響力は意図的に低めに設定する**: 多くのエンジニアがスターやフォロワーを多く持つわけではないため、影響力10〜40が標準レンジ。影響力の高いキャラクターはレア枠となる。

### 性格診断

初回ログイン時または任意のタイミングで性格診断を実施し、一部スキルへの補正を決定する。

### 技術特性

| 種別         | 最大数   | 効果                                               |
| ------------ | -------- | -------------------------------------------------- |
| **主要技術** | 2つまで  | 大会との技術マッチ時、全スキルに +3%               |
| **保有技術** | 上限なし | 主要技術または保有技術に合致しない大会には出場不可 |

## 大会：ハッカソン

### 概要

大会はターン制で進行し、最終ターンまでに積み上げた「開発スコア」を競う。  
対戦相手は**デッキスコアに近い順**でマッチングされる（非同期対人）。リアルタイム対戦は行わず、相手の登録済みデッキに対してシミュレーションを実行する方式。

### ターン構成

ターン数は難易度によって以下の3段階で固定する。

| 難易度 | ターン数（経過日数） | 企画フェーズ | 実装フェーズ |
| ------ | -------------------- | ------------ | ------------ |
| 初級   | 7ターン              | 前半2ターン  | 残り5ターン  |
| 中級   | 10ターン             | 前半2ターン  | 残り8ターン  |
| 上級   | 14ターン             | 前半2ターン  | 残り12ターン |

**企画フェーズ（前半2ターン）**  
企画力と影響力で開発進捗が積み上がる。

**実装フェーズ（残りターン）**  
実装力・継続力・開発速度で開発進捗が積み上がる。

### デッキ規制

- デッキに編成できるキャラクターの最大人数は **7人**
- 毎ターン、その時点のフェーズでデッキ全員が行動する

### 勝利条件

```
開発スコア = 実装フェーズの累計開発進捗 × (全メンバーの影響力合計 + 全メンバーの企画力合計)
```

最終ターン終了時点で**開発スコアが高い方が勝利**。  
同点の場合は全メンバーの実装力合計が高い方を勝者とする。

> **設計意図**: 実装フェーズの進捗が勝利条件のベースとなり、企画力・影響力が乗数として機能する。
> 実装力・開発速度の高いキャラクターが進捗を稼ぎ、企画力・影響力の高いキャラクターがそれを増幅させるため、どのスキルも勝利に直結する。

### 毎ターンの補正

各ターンの開始時に、体調・モチベーション・イベントの3種類の補正が独立して抽選される。

#### 体調

| 状態           | 効果          | 発生確率 |
| -------------- | ------------- | -------- |
| すっきり寝れた | 実装力 +10%   | 20%      |
| 普通           | 補正なし      | 70%      |
| 体調不良       | 実装力 -10%   | 9%       |
| 病気           | 全スキル -30% | 1%       |

#### モチベーション

| 状態       | 効果          | 発生確率 |
| ---------- | ------------- | -------- |
| 最高       | 開発速度 +15% | 18%      |
| 普通       | 補正なし      | 80%      |
| やる気なし | 開発速度 -20% | 2%       |

#### アクシデント・ラッキーイベント

毎ターン、デッキ全員の影響力の平均値をもとに抽選される。  
ラッキーイベントとアクシデントは独立して判定する（両方発生しうる）。

| 種別                   | 内容                                  | 発生確率                         |
| ---------------------- | ------------------------------------- | -------------------------------- |
| ラッキー：円滑な開発   | そのターン全員の開発速度 +5%          | `影響力（平均） × 0.1` %         |
| アクシデント：仕様変更 | そのターンの開発進捗が現時点から -30% | `(100 - 影響力（平均）) × 0.1` % |

> **補正式の例**:
>
> - 影響力（平均）= 100 → ラッキー確率 10% / アクシデント確率 0%
> - 影響力（平均）= 50 → ラッキー確率 5% / アクシデント確率 5%
> - 影響力（平均）= 0 → ラッキー確率 0% / アクシデント確率 10%

## マッチングシステム

### 概要

リアルタイム対戦は行わない。パワプロの「栄冠ナイン」や艦これの「演習」と同様に、**他プレイヤーが事前にデータベースへ登録したデッキ**の中から自分のデッキスコアに近いものを取得し、それに対してシミュレーションを実行する非同期方式を採用する。

相手プレイヤーがオンラインである必要はなく、常に対戦が可能。

### デッキ登録

- プレイヤーはいつでも「デッキを登録する」操作で自分の現在のデッキをデータベースに保存できる
- 登録されたデッキはデッキスコアとともにサーバーに保持され、他プレイヤーのマッチング対象となる
- デッキを更新すると登録内容も上書きされる（常に最新の登録デッキが対戦相手として使われる）

### デッキスコア

マッチングの基準となる指標。デッキの総合戦力を0〜1000で表す。

```
デッキスコア = Σ（各メンバーのスキル加重合計） × スケーリング係数

スキル加重合計（1人あたり）=
    実装力 × 0.30
  + 開発速度 × 0.25
  + 影響力 × 0.20
  + 企画力 × 0.15
  + 継続力 × 0.10

スケーリング係数 = 1000 / (7 × 100)  ≒ 1.4286
```

> **重み付けの意図**: 勝利条件で最も進捗に貢献する実装力・開発速度を高ウェイトに。影響力はイベント制御として中ウェイト。企画力・継続力は乗数効果があるが個人スキルへの依存度が相対的に低いため低ウェイトとした。

**上限・理論値の例**:

| ケース                                 | デッキスコア |
| -------------------------------------- | ------------ |
| 全員スキル全100（理論最大）            | 1000         |
| 実装特化型 × 7人（実装100 / 他50平均） | 約643        |
| バランス型 × 7人（全スキル60平均）     | 約600        |
| 初心者デッキ（全スキル20平均）         | 約200        |

### マッチングロジック

1. プレイヤーが大会にエントリーすると、自分の現在のデッキスコアを算出する
2. データベースに登録済みのデッキの中から、**同一難易度帯**かつ**デッキスコアが近い順**に相手候補を取得する（スコア差 ±100 以内を優先）
3. 該当するデッキが見つからない場合は、スコア差の許容範囲を段階的に拡大して再取得する
4. 相手デッキが決定したら、バックエンドがシミュレーションを自動実行する
5. 結果（勝敗・開発スコア詳細・ターンごとの補正ログ）が即時通知される

- 相手プレイヤーのオンライン状態に関わらず即座に対戦可能
- 同一プレイヤーのデッキとの連続マッチングは避ける（直近3戦を除外）
- 相手プレイヤーには「自分のデッキが対戦に使用された」旨が通知される（対戦結果も確認可能）
